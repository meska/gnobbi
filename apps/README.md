# Sample mobile apps

Two minimal apps over the UniFFI bridge in `crates/matrix-mobile`: sign in, sync, room list (live), send a text
message. Colours and measures come only from the generated design tokens
(`crates/matrix-domain/design/generated/DesignTokens.{swift,kt}`).

- `ios/`: SwiftUI, project generated by XcodeGen (`project.yml`).
- `android/`: Kotlin + Compose, Gradle (AGP 8.11, Kotlin 2.2, compileSdk 36, minSdk 24).
- `fixture/servers.py`: disposable Synapse + Tuwunel (docker) behind one TLS proxy, accounts `gnobbi-test-a/b`,
  three rooms each. Random passwords and a throw-away CA live in `fixture/.run/` (git-ignored). `down` removes everything.

## Build and run

    python3 apps/fixture/servers.py up          # prints the path of fixture.json (urls, passwords, CA)
    scripts/mobile.sh ios | android | bindings  # Rust side (see the script header for prerequisites)

iOS (macOS + Xcode): `apps/ios/stage.sh && (cd apps/ios && xcodegen)`, then
`xcodebuild -project GnobbiMobile.xcodeproj -scheme GnobbiMobile -destination 'generic/platform=iOS Simulator'
-derivedDataPath DerivedData ARCHS=arm64 ONLY_ACTIVE_ARCH=YES CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=YES
CODE_SIGNING_REQUIRED=NO build` and `apps/ios/run-sim.sh <label>`.

Android: `apps/android/stage.sh && (cd apps/android && ./gradlew assembleDebug)` and `apps/android/run-emulator.sh <label>`.

Test servers use a private CA: both apps accept it in debug builds only, from `GNOBBI_TEST_CA` (iOS env) / the `ca_b64` intent extra (Android).
Debug builds also take `GNOBBI_TEST_HOMESERVER/USER/PASSWORD/SEND` (iOS env) or the `homeserver/user/password/send`
extras (Android) to sign in and send once without typing; release builds ignore them.

## Findings (for MOBILE.md)

Verified on iOS 26.5 simulator (Xcode 26.6, static libs built with Xcode 27.2) and on an Android 35 arm64 emulator,
both against Synapse and Tuwunel: sign-in, room list with previews/unread, send from the app, session restore on relaunch (iOS).

1. `data_dir` must not be pre-created by the platform: the bridge creates it 0700 and refuses a looser one
   (`Storage`). It must also be the canonical path: Android's `filesDir` is `/data/user/0/...`, a symlink to
   `/data/data` (use `canonicalFile`).
2. Android refuses reqwest's "extra roots merged with platform roots" (`rustls-platform-verifier could not load extra certs`,
   surfaced as `InvalidInput`). Engine now uses `tls_certs_only` on Android when a trust root is given
   (`auth::with_trust_roots`). Without a trust root the platform verifier is expected to need its JNI/Kotlin component initialised (reading of reqwest 0.13 source, not run against a public server):
   NOT done, so Android cannot yet reach a public (publicly-signed) homeserver.
3. Android SELinux denies `link(2)` to apps: the atomic "publish without overwrite" (`session.pending` ->
   `session.sealed`, `active-account`) failed with `Storage`. `fsx::publish_new` uses check-then-rename on Android.
4. iOS `SecItemAdd` needs an application identifier: an unsigned simulator build (`CODE_SIGNING_ALLOWED=NO`) fails with
   `SecretStore`; ad-hoc signing (`CODE_SIGN_IDENTITY=-`) is enough, no certificate.
5. `scripts/mobile.sh ios` output builds with a newer Xcode than the one linking it (26.6 links libs built with 27.2). A
   `generic/platform=iOS Simulator` build also asks for x86_64: pass `ARCHS=arm64`.
6. UniFFI naming: Swift error cases keep the Rust case (`MobileError.Storage`), Kotlin turns the error enum into
   `MobileException` (also the type of the `on_send_result` argument) and enum values into `SCREAMING_CASE`. `u64` is
   `ULong` in Kotlin. Kotlin needs JNA (`jna:...@aar`) and kotlinx-coroutines for the async functions.
7. Async: `sign_in`/`restore_session` are plain `async` in both languages (tokio runtime is inside the bridge); listener
   callbacks arrive on the bridge's own thread, so both apps hop to the main actor (Swift) / write Compose snapshot state
   (Kotlin) from there. No FFI problem seen with this.
8. Keyboard: Android verified (soft keyboard, `imePadding`, send bar stays above it, "Invia" sends). Typed text keeps the
   trailing newline from Enter in the multi-line field: trim in the UI. iOS keyboard NOT exercised (no way to tap/type in
   the simulator from a script here).
9. Android `adb shell am start --es` re-splits arguments on the device: pass one string with quoted values.
10. Not covered: Android run of the release build, device builds (aarch64-apple-ios), the 156 MB debug APK (unstripped `.so`).
